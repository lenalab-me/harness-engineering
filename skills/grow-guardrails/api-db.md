# API と DB の関所

HTTP で JSON を返す API と、その裏の DB を持つアプリのためのルール。どのルールも「何をするか」と「どこで落とすか」を対にしている。落とす場所が無いルールは、落とす場所を作ってから書く。

ルールは技術に依らない。落とし方は技術ごとに変わるので、例を 2 つ添える。左は持ち主の Cloudflare のアプリ（Workers・D1・Hono・Zod・React。非公開）で、実際に入れた検査の名前を括弧に書いた。右は Go のバックエンドと RDB で使うならの例で、まだ使い込んでいない。

コードの型（配るキット）は作らない。技術の組み合わせが変わると外れるため。同じ組み合わせのアプリは、手本のアプリから芯を写して始める。2 つ目で同じものを写したら、そこで初めて配る形を考える。

[SKILL.md](SKILL.md) の「始めるときに決めること」（正本、データの形の置き場所、確かめる役）を、API と DB に当てはめたもの。全部を最初に入れない。「いつ」の列が「最初から」のものだけを始めに入れ、ほかはサインが出たときに入れる。

## 約束と入口

| ルール | いつ | Cloudflare（TS） | Go・RDB |
|---|---|---|---|
| API の約束（パス・権限の段・入力と応答の形・上限）は 1 か所に宣言し、全ルートを機械で歩いて確かめる。サーバーも画面もそこから作る | 最初から | Worker にも DOM にも依らないパッケージにルートの表を置き、サーバーは表から登録し、画面は表から呼ぶ。表に無いルートを足すと落ちる（route-table）。表のパッケージに Worker や DOM の型を持ち込むと型検査が落ちる | OpenAPI を正本にし、生成したサーバーのインターフェース（oapi-codegen の strict server など）で、実装の無いルートをコンパイルで落とす。ルーターに登録したルートと仕様を突き合わせるテスト |
| 権限は段（公開・ログイン・管理・対象ごと）で宣言し、全ルートで、断られることと、断ったときに書き込みや外への呼び出しが無いことを確かめる | 最初から | 表の `access`。表を歩いて 401・403 と副作用なしを見る（route-authz-inventory）。ルートの中で権限の関数を呼ぶと落ちる（permission-gate） | 仕様の `security` と拡張の項目で段を書き、登録したルートを歩いて、ログインなし・別の利用者で叩くテスト |
| 外に晒す入口は、回数・本文の大きさ・文字列と配列の長さの上限を、全ルートに書かせる（付けないなら理由を書く） | 外に公開するとき | 表の `rateLimit`・`maxJsonBytes` を必須にし、書き忘れを型検査で止める。公開・書き込みのルートで付けないと落ちる（route-limits）。文字列と配列に `.max()` が無いと落ちる（input-bounds） | 仕様の `maxLength`・`maxItems` が無い項目を探すテスト。本文の上限は共通の middleware 1 本で |
| エラーの形は 1 つにし、エラーの種類は 1 か所の一覧に置く。認証の失敗・存在しないパス・予期しない例外も同じ形 | 最初から | エラーを作る関数 1 つと、種類から HTTP の状態への表。自分でエラーの本文を作ると落ちる（error-shape）。一覧に無い種類は型検査が止める | エラーの型 1 つと書き出す関数 1 つ。ほかで `http.Error(` などを書くとリンター（forbidigo）で落とす。形は RFC 9457（problem+json）に寄せてもよい |
| 認証は差し替え口を 1 つにする。IdP の名前と SDK は、その中でだけ使う | 最初から | 検証は middleware 1 本、画面はログイン状態の Provider 1 つ、テストは偽物のトークン。IdP の SDK・名前を認証の外で使うと落ちる検査は、まだ無い（足す） | 同じ。IdP の SDK の import を 1 つのパッケージに限る（depguard） |

## 値とデータ

| ルール | いつ | Cloudflare（TS） | Go・RDB |
|---|---|---|---|
| サーバーが持つ情報から決まる値（正誤・点数・合計・名前・誰の要求か）は、サーバーが決める。画面は規則を写さず、表示するだけ。答える前の応答に正解や秘密を入れない | 最初から | 表の入力にサーバーが決める値の名前があれば落とす（server-decides）。答える前の応答のスキーマに正解の名前があれば落とす（question-secrets）。画面のコードに正解の名前を書くと落とす | 仕様の要求と応答のスキーマを歩いて、同じ名前を探すテスト |
| 値の集合（状態・種類など）は 1 か所に置き、DB の CHECK・API のスキーマ・画面の型をそこに合わせる | 2 か所目に書いたとき | 値の集合のファイル 1 つ。DB の CHECK の集合とずれると落ちる（row-schemas） | Go の定数か仕様の enum を正本にし、DB の CHECK（か enum 型）をカタログから読んで突き合わせるテスト |
| DB から読んだ行は、型に通して読む。読み方は 1 か所に閉じる | 最初から | 行を読む関数 2 つ（1 行・複数行）だけを使い、ほかの読み方を落とす（row-reads）。表を足して行の形に足さないと落ちる（row-schemas） | sqlc などで読み取りを生成し、手書きをなくす（列名の誤りも生成のときに落ちる）。生成した包みの外で `Query(` を書くと落とす |
| 正本は 1 つにし、利用者が作った記録は追加だけにする。管理側のデータを消したときに、連鎖削除で利用者の記録を巻き込まない | 利用者の記録を持つとき | 記録の表は、変更（直してよいと決めた列を除く）と削除をトリガーで断る。利用者の表は利用者に外部キーを張り、管理側の表への連鎖削除は使わない（消す代わりに止める） | 同じ。アプリの DB ユーザーから UPDATE・DELETE の権限を外してもよい |
| 集計の写しは DB が保ち、数え直した値と突き合わせる | 写しを持ったとき | トリガーで保ち、書き込みを混ぜるたびに「数え直し EXCEPT 写し」とその逆が空かを見る（aggregate-copies） | 同じ。マテリアライズドビューは更新するまで古いので、「いつも一致」の約束にはならない |

## 重さと移し

| ルール | いつ | Cloudflare（TS） | Go・RDB |
|---|---|---|---|
| 要求 1 回の重さに予算を付ける。数える単位は、上限やお金が付く単位にする | 量で上限やお金が決まる DB を使うとき | 表に読んでよい行数を書き、架空の種の上で全ルートを流して超えたら落とす。種を 2 倍にして増えるルートも落とす（理由つきの一覧だけ許す） | 1 要求の問い合わせの数を数え、N+1 を落とす。大きな表の全件読みを実行計画で落とす。行で課金されないなら、困ってから |
| データを移す SQL は、規模を変えて測ってから本番に流す。見積もりは書き込みだけでなく読みも | 本番のデータを移すとき | 大きな架空の世界をローカルの DB に入れ、データを 2 倍にして読みが 2 倍強を超えないことを測る。見積もりに読みの上限も入れる | 同じ。`EXPLAIN (ANALYZE, BUFFERS)` で規模を変えて比べる |
| 開発のデータは架空の種だけにし、最初から境界値を入れる（長い文・0 埋めの番号・多い件数・空の状態・画像やコード） | 最初から（境界値は画面ができたら） | 種を入れる命令は本番を受け付けない。境界値の見本を画面の検査（はみ出し・基準画像）にかける | 同じ |

## 画面との境目

- **書き込みが成功したら、応答の中身で画面の状態を書き換えず、古くなった読み込みを読み直す.** 応答を使うのは、成功か失敗かと、その場で一度だけ見せる値（発行したコードなど）だけ。サーバーが決める値を、画面がなぞり直さない。キャッシュを入れると「どの書き込みがどの読み込みを古くするか」が画面に散るので、入れるのは、書き込みを画面の切り替えなしに別の場所へ映す必要が出たとき。
- **画面から API を呼ぶ道は 1 本にする.** ほかで `fetch(` を書くと落とす。

## 名前で探す検査の弱さ

ここの検査の多くは、名前や書き方を文字で探す。別の名前で同じ値を受け取る、別の関数名で権限を見る、といった抜け道は見ない。抜け道は、プロジェクトの約束の一覧に「確かめないこと」として書いておく（何を見ないかが分かっていれば、レビューで見られる）。
