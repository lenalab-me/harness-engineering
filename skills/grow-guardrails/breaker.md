# 壊し役

約束の一覧の1行を、テストが本当に守っているかを、テストを書いた役とは別の役に攻めさせる。壊し方を書いた本人が選ぶと、テストが拾うと分かっている壊し方を選びがちになるため。

## 頼むとき（親）

- 壊れても気づきにくい約束（保存の形、再送・競合、権限、生成の結果）を足した・変えたときだけ使う。見た目の約束には使わない。
- `delegate_task` で、`isolation:"worktree"`、テストを書いた役とは別のモデルで起こす。下の指示文に、約束の1行とテストの名前を入れて渡す。
- 1つの約束につき1往復まで。穴を塞いだあとにもう一度当てるのは、利用者が頼んだときだけ。

## 指示文

```text
あなたは壊し役です。次の約束を、テストが本当に守っているかを確かめます。

約束：<約束の一覧の1行>
確かめるテスト：<テストの名前>

この約束を破る、いちばん小さいコードの変更を最大5通り試し、それぞれで check（<コマンド>）を流してください。

壊し方は、人や AI が実際にやりそうな間違いに限ります。
- 呼び出しを1つ忘れる
- 条件を逆にする、境界を1つずらす
- 新しい経路・項目・表を足して、一覧や分岐に載せ忘れる
- 規則を別の場所に写して、片方だけ直す
- エラーを握りつぶす

やらないこと：
- テスト、約束の一覧、check の設定、フィクスチャを変える
- テスト中かどうかを見て分岐する
- 約束の文に書いていないことを破る
- コミット、push

報告：
- check が通ってしまった壊し方：差分と、それが実際に起こりうる理由を1行
- check で落ちた壊し方：落ちたテストの名前
最後に、作業ツリーの変更はすべて捨ててください。
```

## 穴が見つかったら（親）

利用者に見せる前に、穴を1つずつ仕分ける。

- **塞ぐ**：実際に起こりうる間違いで、約束の文がそれを守ると言っている。テストを1本足すか、既存のテストに入力を1つ足す。仕組みは作らない。
- **受け入れる**：起こりそうにない、または塞ぐのに新しい仕組みが要る。塞がずに報告し、約束の一覧の行に「〜は確かめない」と書くかは利用者に聞く。

迷ったら塞がない。
