# サインと関所の対応

左のサインが出たら、右の関所を提案する。例は network-designer（`~/project/prod/network/network-designer`）のコミットで、`git show <ハッシュ>` で中身と「壊して確かめたこと」を読める。そのまま写さず、そのプロジェクトの大きさに合わせて小さく作る。

## データと規則

| サイン | 関所 | 例 |
|---|---|---|
| ひとつ触ると関係ない所が壊れる。画面ごとにデータの形が違う。部品ごとの検査は通るのに、つなぐと壊れる | 保存する形を Schema と基準の例文書に固め、例文書・Schema・コードの型が一致することをテストする | `TestConfigurationExamplesMatchSchemaAndTypes` |
| 同じ絞り込み・同じ更新・同じ判定を、何か所にも書いている | 1か所の関数にまとめ、ほかの場所に書いたら落ちるテストを足す | `listedSite`（ea60758）、`bumpSite`（703ffae）、`modelRef`（66276f6） |
| 画面とサーバーで判定や範囲が食い違う | 画面から規則を消す。サーバーの1か所に置き、`GET /api/rules` のように画面へ配る | 34e2f01 |
| 画面が計算した値（点数・合否・金額）をサーバーがそのまま保存している。答える前の応答に正解が入っている。画面が送った利用者 ID を信じている | サーバーが自分で計算し直すか、認証から決める。書き換えた値を送って無視・拒否されること、応答に見せない項目が無いことをテストする | `TestSchemaErrorNamesTheField`、`authorize`（2baa60b） |
| API の応答の形が、画面の型と知らないうちにずれる | 応答の形はサーバーの構造体だけが決める。実際の応答を見本の JSON に取り、画面の型と過不足なく突き合わせる | e74f123、c9de283 |
| 生成した写し（Schema のコピーなど）が古いまま動き、黙って失敗する | 起動時に元と比べて止め、直し方をメッセージで示す | dd0eb6e |
| 後で権限・排他・利用者を入れたいが、今は入れない | 入口を1か所にし、宣言しないとコンパイルが通らない形にしておく（中身は「全部許可」でよい） | 2baa60b |

## テストと確かめ

| サイン | 関所 | 例 |
|---|---|---|
| テストは「ok」なのに実は流れていない（DB がなくてスキップされた、など） | `check` ではスキップを失敗にする | ea60758 |
| テストのコードを読まないとレビューできない。何を守っているのかわからない | 約束の一覧に「約束 \| テスト名」を書き、挙げた名前が実在するかをテストする | ea60758、f4c1ab7 |
| 「動きました」の報告が信用できない | 専用のポートと DB で起動し、利用者と同じ操作をして証跡を残す検証スキルを作る | a22520b |
| 並列の作業ツリーで、DB やポートがぶつかる | DB 名と証跡の場所を決めるのを1か所（スクリプト1本）にし、作業ツリーごとに分ける | 5a7ba0f |

## 画面

| サイン | 関所 | 例 |
|---|---|---|
| 画面の見た目が知らないうちに変わる | 画面ごとの基準画像を許容0で比べる。ルートの一覧と、画面の一覧を突き合わせる | ef447ee |
| 共通部品がいつの間にか増えたり変わったりする | 部品の内容のハッシュをロックファイルに持ち、更新は利用者の承認で行う。部品と画面は別のコミットにする | 49f3259 |
| 画面ごとに色・余白・文字サイズを直書きしている | 画面ファイルには配置のクラスだけを許す検査を入れる | 9f6a3b9 |
| 部品の見本ページが古くなる | 公開している部品が見本にちょうど1回載り、見本で描かれていることを検査する | e305714 |

## 決まりと記録

| サイン | 関所 | 例 |
|---|---|---|
| 決まりが Claude の記憶にしかなく、別のエージェントや作業ツリーが知らない | AGENTS.md に移す | f52190d |
| AGENTS.md が長くなり、時期で変わる話が混ざる | 毎回守るルールだけを残し、優先順位と後回しは予定の文書へ移す | e134915 |
| 計画が会話や git 管理外の場所に流れ、決めた理由が消える | `docs/decisions/` に置き、書いたあとは書き換えない（変わったら日付つきの節を足す） | 6314001 |

## network-designer での順番

参考のために残す。この順に入れる必要はない。

- 9/16：画面と保存を先に作った。関所はなし。別のエージェントが画面ごとに好きな形を作り、データがばらばらになった。
- 10/2：「ひとつ触るとどこかが壊れる」→ 約束の一覧、`check`、1か所に寄せる（`listedSite`）。
- 10/6：並列で作業するようになった → 検証スキル、作業ツリーごとの DB。
- 10/7〜8：「問題は疎結合かどうかではなく、約束が暗黙なこと」→ Schema と例文書、API の見本、画面から規則を消す。記憶にあった決まりを AGENTS.md へ移す。作り込みすぎたガードを簡素化。
- 10/13：画面を共通部品へ差し替え → ロック、基準画像、画面ファイルの検査、部品の台帳。AGENTS.md を毎回守るルールだけに減らす。
- 10/14：計画書を git に残す。設計書は最後に起こすと決める。権限を後から入れやすいよう、入口を1か所に寄せる。
- 10/15：古い Schema のまま起動して、保存が全部 422 になった（文章では防いでいた事故）→ 起動時の検査にした。
